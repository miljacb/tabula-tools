### ClipView

#### `ClipView#sleep`

```ts
sleep(pose: SleepPose = 'current'): this
```

Fall asleep: freeze `pose` (default: the current frame) into cached
skeleton-space triangles. A sleeping view is skipped by the runtime's
update loop and its clip is not advanced; rendering replays the cached
triangles through the view's transform, tint and alpha (same batch, no
bone, constraint or animation work, no allocation). Hit tests keep
using the frozen pose. Calling `sleep()` again re-freezes. {@link wake}
or {@link play} resume.

#### `ClipView#setSlotText`

```ts
setSlotText(slot: string, text: SdfText | null, options?: SlotTextOptions): this
```

Draw `text` in slot `slot`: at the slot's place in the draw order (in
front of the slots before it, behind the ones after it) and in the same
batch as the skeleton. The text follows the slot's bone (position,
rotation, scale), takes the slot's color and alpha (fades and color keys
apply), hides with the bone, and inside a clipping attachment's range
draws only the glyphs whose center is inside the clip. The text's own
`x`, `y`, `rotation`, `scale`, `tint` and `alpha` apply on top, in bone
space. A sleeping view keeps drawing it live, so a number roll does not
wake the view. Pass null to remove it. Pool release removes all slot texts.

The text must not be in the display list (the view draws it); create it
with `runtime.createText` so number rolls keep updating. The view does not
destroy it. One text per slot; the slot usually holds no attachment (a
placeholder slot in the Spine project), otherwise the text draws over it.

**Throws:** if the skeleton has no slot `slot`, or `text` has a parent.

**Example**

```ts
const win = runtime.createText('', { font, fontSize: 48, anchorX: 0.5, anchorY: 0.5 });
plate.setSlotText('winAmount', win).play('show');
win.rollTo(1250, { duration: 1.5, format: NumberFormats.money });
```

## `src/pixi-v8/pool.ts`

### ClipViewPool

*class* — [`src/pixi-v8/pool.ts`](../../../src/pixi-v8/pool.ts)

```ts
class ClipViewPool extends ViewPool<ClipView, TabulaAsset>
```

A pool of views of one asset. {@link acquire} hands out a view that is
indistinguishable from a new one (setup pose, awake, no listeners, identity
transform, no parent); {@link release} resets it (state, tracks,
listeners, tint, skin, attachments, transform, parent) and parks it asleep
so it costs nothing per frame. Releasing a view twice is ignored with a
warning.

**Example**

```ts
const pool = runtime.pool(symbolsAsset, { prewarm: 60, max: 120 });
const view = pool.acquire({ skin: 'cherry' });
reel.addChild(view);
view.play('spinStop', { sleepOnComplete: true });
// ...when the symbol is cleared:
pool.release(view);
```


false (and warns once) when the view is already free; destroyed views are
dropped. Throws for views that do not belong to this pool.

{@link ClipViewPoolOptions.budgetMs}, so start-up frames are not hit.
Resolves when done. Never exceeds `max`.

```ts

```

### loadAtlasTextures

*function* — [`src/pixi-v8/assets.ts`](../../../src/pixi-v8/assets.ts)

```ts
function loadAtlasTextures(atlas: AtlasData, baseUrl: string, options: PageTextureOptions = {}): Promise<Map<string, TextureSource>>
```

Load the page textures of `atlas` from `baseUrl`. Images go through Pixi's
Assets loader: pages flagged `pma` are uploaded as-is, others are
premultiplied on upload, so the shader always samples premultiplied
texels. With a texture manifest, the page files of the chosen tier load
instead (same atlas: UVs are normalised by the atlas page size), and KTX2
pages are transcoded for the renderer's GPU. A KTX2 page that fails
(no transcoder, unsupported file) falls back to the tier's image.

### TabulaRendererOptions

*interface* — [`src/pixi-v8/runtime.ts`](../../../src/pixi-v8/runtime.ts)

| Member | Description |
